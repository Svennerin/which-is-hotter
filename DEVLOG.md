# Dev log

One entry per step: what was done, and the one-line reason why.

1. **Scaffold (Vite `react-ts`, Tailwind v4, Vitest, TanStack Query, d3-geo, topojson, world-atlas).** Locked the stack from the brief first so every later step builds on the same tools. Cleaned the template demo files.
2. **Verified Open-Meteo by calling it.** Read the terms and probed real responses before designing around them. Findings: `current=temperature_2m,is_day` works; a multi-location request returns an *array* (a single location returns a bare object); 500 coordinates fit in one GET but 1000 fails with `414` on URL length; the free tier's 600/min limit counts *locations*, not requests (I hit a `429` myself), so a 70-city pool costs 70 of the minute's budget. Terms: non-commercial, CC BY 4.0 attribution required.
3. **City list generator (`scripts/generate-cities.mjs`).** A reviewed, committed static list beats live geocoding: no extra request to fail in production, and pairing stays predictable. Natural Earth 110m places filtered to population >= 500k plus a hand-picked set of small capitals so Oceania and the Pacific are not empty. Result: 183 cities, 36 in the southern hemisphere. Continents come from a join with Natural Earth countries; the script fails loudly on any city without one.
4. **Sun position and day/night helper (`src/geo/sun.ts`).** The terminator shading is only trustworthy if the sun maths is. Unit-tested at solstices/equinoxes, then checked live against Open-Meteo's `is_day` for all 183 cities: 181 agree, and the other two (La Paz, Santiago) are within 0.7° of the terminator where the two definitions of "sunrise" legitimately differ.
5. **Open-Meteo client (`src/api/openMeteo.ts`).** Parse defensively into our own types: handles the single-object quirk, drops locations with null values instead of failing the game, treats the timezone-less timestamp as UTC, and flags HTTP 429 as a distinct "rate limited" error.
6. **Pairing logic (`src/game/pairing.ts`) with tests.** The subtle part of the project, so it is pure (injected RNG, no I/O). Rules (gap, distance, latitude difference as a climate-zone stand-in, no repeats) live in `config.ts`. Greedy selection by score (different continents and distance rewarded, plus jitter) keeps it readable; the gap is rounded to one decimal so floating-point noise cannot flip a boundary case.
7. **Game loader with fallback ladder (`src/game/loadGame.ts`).** Strict rules, then relaxed rules on the same data (free), then one refetch, then a shorter game. A failed second request keeps the first batch rather than throwing a good game away. Injected fetcher so the ladder is tested without a network.
8. **Match reducer (`src/game/matchReducer.ts`).** Progress through a game is a small reducer with guards against double clicks and out-of-order actions, tested separately from the UI.
9. **Map geometry (`src/map/projection.ts`, `nightShading.ts`, `layers.ts`).** The hardest visual part, so it is built only from d3-geo built-ins (no hand-written geometry, per the brief). Rotate the globe to centre on the pair's midpoint (this moves d3's antimeridian cut away from the cities, which fixes dateline pairs), `fitExtent` to two buffer circles (so same-latitude pairs cannot collapse to a zero-height box), clamp zoom between whole-world and 6x. Night is four stacked `geoCircle`s at 90/96/102/108° from the anti-solar point. Unit-tested for dateline, same-latitude, very close and extreme pairs at phone and desktop sizes.
10. **Visual QA harness (`src/qa/MapLab.tsx` + `playwright/map.spec.ts`).** A dev-only page renders any pair at any UTC time and size with no network, so the QA matrix is repeatable: 13 cases (far, tight, three dateline pairs, same-latitude, polar, edge labels) at phone and desktop sizes. Uses the installed Edge, so no browser download. The lab is behind `import.meta.env.DEV`, so it is not in production builds.
11. **QA finding: night-side borders vanished.** Looking at the screenshots, grey borders had almost the same luminance as shaded land, breaking a brief requirement. Fix: keep dark borders everywhere and add a second light pass of borders and coastline clipped to the night polygon. No change to the geometry, so both passes always agree.
12. **UI, state and request handling.** Three views from one `useState`; `GameView` owns the single request through TanStack Query (retry twice for network errors, never for a 429 or an empty result, never refetch on focus because rounds must not change mid-game). Loading, error, rate-limit and empty states all have a retry/back action. Focus moves to "Next round" after a guess and to the round heading after that.
13. **Bug found by the first browser run:** effects written as `useEffect(() => window.scrollTo(0, 0))` returned a value, which React rejects, and the whole app rendered blank. Block bodies fixed it. Unit tests could not have caught this; it is why the browser tests exist.
14. **Browser tests against a mocked API, run on the production build.** The first run saw two weather requests per game: React StrictMode double-mounts effects in dev. That is a dev-only artifact, so the game tests run against `vite preview` instead, which is also closer to what ships. Covers a full 10-round game, exactly one request per game, keyboard-only play and focus, accessible map label, error + retry, 429 handling, empty state, loading state and attribution. Added an axe-core audit over every view (zero violations).
15. **Live tuning of the pairing thresholds changed the design.** `npm run tune` pulls real pools: the strict rules filled a full game every time, but mean pair distance was 12,358 km and 120/120 pairs crossed continents. Rewarding distance made every round a world map and the tightly zoomed views never appeared. Replaced the distance reward with distance bands (near < 5,000 km, mid, far > 10,000 km), filled nearest-first with caps of 3/4/4; the live result is exactly 3 near / 4 mid / 3 far per game.
16. **Bundle split.** The 50m country geometry is ~750 kB, which the home screen does not need. The map is lazy-loaded and preloaded when Start is clicked, so it downloads in parallel with the weather request. Initial JS is 91 kB gzipped; the map chunk is 255 kB gzipped.
17. **Production smoke test against the real API, README, and deploy prep.** `live.spec.ts` checks, on a production build, that the map data is present, the cross-origin request to Open-Meteo returns 200, and there are no failed requests or console errors. It takes `LIVE_URL`, so the same test runs against the deployed Vercel URL once it exists.
