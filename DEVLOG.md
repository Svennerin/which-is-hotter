# Dev log

One entry per step: what was done, and the one-line reason why.

1. **Scaffold (Vite `react-ts`, Tailwind v4, Vitest, TanStack Query, d3-geo, topojson, world-atlas).** Locked the stack from the brief first so every later step builds on the same tools. Cleaned the template demo files.
2. **Verified Open-Meteo by calling it.** Read the terms and probed real responses before designing around them. Findings: `current=temperature_2m,is_day` works; a multi-location request returns an *array* (a single location returns a bare object); 500 coordinates fit in one GET but 1000 fails with `414` on URL length; the free tier's 600/min limit counts *locations*, not requests (I hit a `429` myself), so a 70-city pool costs 70 of the minute's budget. Terms: non-commercial, CC BY 4.0 attribution required.
3. **City list generator (`scripts/generate-cities.mjs`).** A reviewed, committed static list beats live geocoding: no extra request to fail in production, and pairing stays predictable. Natural Earth 110m places filtered to population >= 500k plus a hand-picked set of small capitals so Oceania and the Pacific are not empty. Result: 183 cities, 36 in the southern hemisphere. Continents come from a join with Natural Earth countries; the script fails loudly on any city without one.
4. **Sun position and day/night helper (`src/geo/sun.ts`).** The terminator shading is only trustworthy if the sun maths is. Unit-tested at solstices/equinoxes, then checked live against Open-Meteo's `is_day` for all 183 cities: 181 agree, and the other two (La Paz, Santiago) are within 0.7° of the terminator where the two definitions of "sunrise" legitimately differ.
5. **Open-Meteo client (`src/api/openMeteo.ts`).** Parse defensively into our own types: handles the single-object quirk, drops locations with null values instead of failing the game, treats the timezone-less timestamp as UTC, and flags HTTP 429 as a distinct "rate limited" error.
6. **Pairing logic (`src/game/pairing.ts`) with tests.** The subtle part of the project, so it is pure (injected RNG, no I/O). Rules (gap, distance, latitude difference as a climate-zone stand-in, no repeats) live in `config.ts`. Greedy selection by score (different continents and distance rewarded, plus jitter) keeps it readable; the gap is rounded to one decimal so floating-point noise cannot flip a boundary case.
7. **Game loader with fallback ladder (`src/game/loadGame.ts`).** Strict rules, then relaxed rules on the same data (free), then one refetch, then a shorter game. A failed second request keeps the first batch rather than throwing a good game away. Injected fetcher so the ladder is tested without a network.
8. **Match reducer (`src/game/matchReducer.ts`).** Progress through a game is a small reducer with guards against double clicks and out-of-order actions, tested separately from the UI.
